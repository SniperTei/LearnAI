# RAGAS 学习笔记（RAG 评估）

> 定位一句话：**把"我的 RAG 好不好"从感觉变成分数**。
> RAGAS = RAG Assessment，开源框架，判卷官是 LLM（LLM-as-judge）。
> 本笔记对照 FoodRAG 手搓体系整理，出处：2026-11-02 FoodRAG 主线学习。

---

## 一、大图景：三层体检体系

| 层 | 是什么 | FoodRAG 对应 | 成本 |
|---|---|---|---|
| **trace** | 单发监控录像，看这一单答案哪来的 | ask_core 返回的 trace dict（已通车） | 零 |
| **确定性 eval** | 客观题答题卡，批量回归 | 手搓 eval.py + data/eval_cases.jsonl（待造） | 零，秒出，结果永远稳定 |
| **RAGAS** | 作文阅卷老师，评自由文本质量 | 待接入 | 每题多次 LLM 调用，慢，花钱，分数会抖 |

**顺序原则：便宜的稳定的指标先用上，贵的会抖的指标按需加。**
出问题再优化（被动挨打）→ 改代码跑考卷（回归测试）→ bug 再犯当场被抓。

---

## 二、RAGAS 的考卷：四样东西

每道题收一个四元组，**前三样全在 FoodRAG 的 trace 里躺着**：

```
{
  question:     问题          ← 用户输入
  contexts:     检索到的证据   ← trace.evidence 对应的原文
  answer:       最终答案      ← reply
  ground_truth: 标准答案      ← 人写的（贵！只有算召回率才必须要）
}
```

架构启示：trace 合同打好了，评估的地基就有了。

## 三、四个核心指标

| 指标 | 判什么 | 裁判怎么干活 | 要标准答案吗 | 做菜类比 |
|---|---|---|---|---|
| **Faithfulness 忠实度** | 答案只来自证据吗（防幻觉） | 把答案**拆成一条条说法**，逐条回证据查出处，得分=有出处的说法÷总数 | ❌ | 菜端上桌，每样食材都得出示小票 |
| **Answer Relevancy 答案相关性** | 答非所问吗 | **从答案反推问题**（生成3个候选问题），和原问题算向量相似度 | ❌ | 问锅包肉他答烤串——反推出的问题对不上 |
| **Context Precision 上下文精确率** | 检索回来的证据多少真用上了；有用的有没有排前面 | 逐块证据判"这题用得上吗"，按排名加权（有用的排前面分更高） | ❌ | 采购回来的食材，几样真的下了锅 |
| **Context Recall 上下文召回率** | 该检到的都检到了吗 | 把**标准答案**拆成说法，逐条查证据里有没有 | ✅ | 菜谱要的食材，冰箱里齐了吗 |

### 要点

1. **忠实度=查账**。答案"焯水炖40分钟、芸豆必须炖熟"→拆两条→逐条对证据。LLM 嘴爽写"炖90分钟"而证据没有→那一条挂→掉分。
   FoodRAG 实例：佛跳墙拒答测试 = 手搓版忠实度考试。
2. **相关性=反推问题的骚操作**。直接判"切题吗"裁判说不清，倒着来：答案→反推问题→和原问题算相似度。低分=答非所问。
   FoodRAG 实例：历史带锁没生效、证据串台那次，这个指标当场能抓。
3. **前三个无参考（reference-free），第四个必须 ground_truth**。无参考是 RAGAS 出名卖点——能空手评估线上日志；但召回率躲不掉人写的标准答案。

### 历史 bug 对号入座

| FoodRAG 事故 | 该挂的指标 |
|---|---|
| 佛跳墙幻觉（未发生，拒答✓） | Faithfulness（通过了） |
| 人均只在 metadata 没进正文，LLM 说"没有人均信息" | **Context Recall**（标准答案有人均80，证据正文里没有=该检到的没检到） |

## 三·补 公式拆解（LLM 打分，算术收尾）

> 四个公式全是简单算术，脏活（这句话有没有出处？这块证据有没有用？）全塞给 LLM 打 0/1。
> LLM-as-judge 的设计哲学：**把理解力外包给模型，把算术留给自己**——
> 和"来源盖章"同款思想：确定性的事交给代码。

### 1. Faithfulness 忠实度 = 有出处的说法 ÷ 总说法

```
Faithfulness = Σ I(cᵢ, V) / K
```

答案拆出 K 条说法，I(cᵢ,V) = 第 i 条在证据 V 里找得到出处吗（1/0，LLM 打的分）。
判一道题调两次 LLM：一次**拆说法**（decompose）、一次**逐条对账**（verify），最后除法归代码。

#### 流水线全例（土豆芸豆炖排骨）

证据（账本原文）：做法=焯水去血沫→炒香葱姜八角→生抽老抽上色→加热水小火炖40分钟→下土豆芸豆再炖20分钟收汁；注意点=芸豆必须彻底炖熟（有毒）；炖加热水肉不柴。

LLM 答案 = 上面这些 + 多一句"**建议炖90分钟以上口感更好**"。

**① 拆说法**（LLM 干活Ⅰ）→ 拆出 8 条：焯水✓炒香✓上色✓炖40分✓再炖20分✓、**炖90分以上**、芸豆煮熟✓、加热水✓

**② 逐条对账**（LLM 干活Ⅱ）→ 7 条有出处；"炖90分钟"证据里没有 → ✗

**③ 套公式**（代码干，零 LLM）→ **7/8 = 0.875**

细节三则：
- **为什么拆？** 整段判的话 8 句里 7 句对，裁判睁一只眼就放行，错句藏在好话里；
  拆成最小说法逐条对，无处藏身——查账要逐笔对发票，不能只看总账。
- **幻觉的典型姿势**：c6 不是胡编，是 LLM 把训练时的通用厨艺知识当"好心补充"混进来。
  对 RAG 来说证据里没有的就是没有——受控生成在**生成前拦**，Faithfulness 在**生成后验**，一防一查。
- **与召回率对称**：同一套拆账动作，忠实度查"答案的说法"，召回率查"标准答案的说法"。

#### 忠实 ≠ 正确（易混点）

Faithfulness 查**出处**（小票呢？），不查**真伪**（小票是不是真发票）。
"正确"在 RAG 世界观里拆成两问：①忠于证据吗→Faithfulness（生成层的锅）；
②证据本身对吗→语料质量（备菜线的锅：账本人均填错，答案忠实搬运照拿满分）。
真要评"答案正确性"用第五指标 **Answer Correctness**（有参考，和 Recall 同档贵）。
做菜类比：Faithfulness 管"菜里食材都出自小票没偷加"；食材新不新鲜归采购质检台（prep 质检脚本）管。

四象限速查：如实转述=双高；混进"炖90分钟"=**Faithfulness低Relevancy高**；
证据串台如实介绍烧烤店=**Faithfulness高Relevancy低**；编店答锅包肉=双低。
两个指标管的坑不同，互补不重复。


### 2. Answer Relevancy 答案相关性 = 反推问题与原问题的相似度取平均

```
Relevancy = (1/n) Σ cos( E(q), E(qᵢ) )
```

流水线三道工序：**①反推问题（LLM）→ ②算余弦相似度（嵌入模型）→ ③取平均（代码）**。

#### 全例（证据串台案）

问题 `锅包肉怎么做？`，答案（串台后如实转述）`尚唐烧烤的油边最好吃，人均80，在上塘地铁站D出口……`

① 反推出 3 个问题（LLM）：`哪家烧烤店油边好吃？` / `尚唐烧烤人均多少？` / `尚唐烧烤在哪？`
② 原问题与三者余弦相似度（嵌入算，bge-m3 同门手艺）：0.12 / 0.10 / 0.11
③ 平均 = **0.11**，低分当场抓住答非所问。
对照组（正常答案反推出"锅包肉怎么做/做法步骤"）→ 0.92。

细节：**为什么绕"反推"这个弯？** 直接问裁判"切题吗"容易给面子；反推是客观化手段——
答案的信息内容决定能反推出什么问题，答案只谈店→反推出全是"哪家店"→和"怎么做"必然不相似。
**数字不会给面子。** 局限：只判切题不判真实——答案若是关于锅包肉的编造照样高分，
所以它和 Faithfulness 是互补一对（一个管真假，一个管对题）。

### 3. Context Precision 上下文精确率 = 平均精确率 AP（搜索引擎排序老配方）

```
CP = (1/R) Σₖ P@k × vₖ        （只在 vₖ=1 的位置累加，R=有用总数）
P@k = 前 k 名里有用几块 ÷ k      （vₖ 由 LLM 判 1/0）
```

流水线两道工序：**①逐块判有用（LLM）→ ②算 AP（代码）**。

#### 全例（周六8人硬菜局，k=8）

| 排名 | 证据 | vₖ | P@k |
|---|---|---|---|
| 1 | 锅包肉 | ✓ | 1/1=1.0 |
| 2 | 肉骨茶 | ✓ | 2/2=1.0 |
| 3 | 拌黄瓜 | ✗ | — |
| 4 | 炖排骨 | ✓ | 3/4=0.75 |
| 5 | 烫西兰花 | ✗ | — |
| 6 | 红烧排骨 | ✓ | 4/6≈0.67 |
| 7 | 可乐鸡翅 | ✗ | — |
| 8 | 麻辣小龙虾 | ✓ | 5/8=0.63 |

AP = (1.0+1.0+0.75+0.67+0.63)÷5 = **0.81**
对照组：**同样 5 块有用**但全垫底（排 4~8）→ (0.25+0.40+0.50+0.57+0.63)÷5 = **0.47**
→ 捞到的一样多，分差悬殊：**AP 专罚"有用的不排前面"**。

细节：**和 Hit@k 的分工**——Hit@k 管"捞到没"（标准菜在不在前k），AP 管"排好没"（有用块排第几）。
drug_rag 上 gte-rerank-v2 重排，优化的正是 AP：召回 30 块里把最相关的顶进前 5。

### 4. Context Recall 上下文召回率 = 对得上的说法 ÷ 标准答案总说法

```
Recall = 对得上的说法数 / 标准答案拆出的总说法数
```

流水线三道工序：**①拆标准答案（LLM）→ ②逐条查证据（LLM）→ ③占比（代码）**。
和 Faithfulness 同一套拆账动作，只是查账对象从"答案"换成"人写的标准答案"。

#### 全例（人均事故原案）

问题 `大富烧鸡坂田店人均多少？在哪？`
标准答案（人写）：`人均80元；地址龙岗区坂田街道和磡北路19号。`
检索证据（事故当时，人均躺在 metadata 没进正文）：
> 大富烧鸡（坂田店）烧鸡 招牌菜：烧鸡 特点：烧鸡巨好吃！！ 地址：龙岗区坂田街道和磡北路19号

① 拆标准答案 → 2 条：c1=人均80；c2=地址
② 对账：c1 ✗（证据**正文**真没有，裁判只看正文，metadata 救不了）；c2 ✓
③ **Recall = 1/2 = 0.5**（修好暗桩后 → 1.0）

细节：**Recall 是分锅指标**——人均那次 LLM 答"没有人均信息"是诚实的，
Faithfulness 给那个答案满分（真没编），只有 Recall 把板子打对地方：证据不够=备菜线的锅。
**诊断口诀：Faithfulness 低=生成的锅（答案嘴爽）；Faithfulness 高但 Recall 低=检索/语料的锅（答案诚实但证据缺）。**
四个指标里 Recall 唯一必须人写标准答案（判"该检到"得先知道"该检什么"）——考题最贵。

### 公式家族（只有三种形状）

| 形状 | 谁在用 | 本质 |
|---|---|---|
| **占比**（x÷总数） | 忠实度、召回率 | 查账通过率——一个查**答案**的说法，一个查**标准答案**的说法，对称的一对 |
| **排序加权占比** | 精确率 | 信息检索祖传 AP |
| **向量相似度均值** | 相关性 | 嵌入+余弦，与检索层同门 |

LLM 裁判干的活只有三种：**拆说法、打 0/1、反推问题**——公式骨架里没有一个字需要理解语义。

## 四、RAGAS vs 手搓 eval.py：两层不是替代

| | 手搓 eval.py | RAGAS |
|---|---|---|
| 判卷方式 | 确定性代码对答案 | LLM 裁判 + 嵌入相似度 |
| 题型 | 客观题：路由命中率 / Hit@k / 拒答正确率 / 反问正确率 | 主观题：四个核心指标 |
| 覆盖 | RAGAS **不管**的部分：选仓、槽位、拒答、trace | 代码**判不了**的部分：自由文本质量 |
| 成本 | 零，秒出，永远稳定 | 每题至少几次 LLM 调用，慢，花钱 |
| 命门 | 只能考有唯一答案的事 | 裁判自己也会看走眼（结构规整≠内容真实） |

**RAGAS 假设检索已经发生**，只评（问题，证据，答案）三元组好坏——判单树错走仓、槽位乱反问，它一个都测不出。

## 五、两个彩蛋

1. **自动出题（testset generation）**：喂账本（jsonl），LLM 从语料反向造题——拿"锅包肉做法"证据造出"锅包肉怎么做"，标准答案自带。
   适合快速凑批量考卷；但机器造的题没有人报 bug 来的真（用户问法更刁钻："邀请姐姐姐夫来家里吃饭"）。
   出题三来源：**bug 变考题（最真）> 自动造题（凑数）> 人工手写（最贵）**。
2. **裁判档位决定判卷质量**：qwen3:4b 当裁判勉强（小模型判卷自己都抖，同一答案两次打分可能不同）；真要用，裁判换 DashScope flash（几厘钱一题）。
   评估本身也是 LLM 应用——增强层哲学同样适用。
