## 1. ReAct：想一段、动一下、看一眼

### 1.1 三件套循环（核心骨架）

```
Thought（思考）→ Action（行动）→ Observation（观察）→ 回到 Thought → … → Finish
```

- **思考**：厨师的内心戏——分解问题 / 给观察记账 / 更新计划 / 调整打法 / 综合收工
- **行动**：调工具（论文里只有 Search / Lookup / Finish 三个）
- **观察**：环境递回来的实况，**不是模型编的**——这是 ReAct 防幻觉的根：事实从外面进来

### 1.2 论文消融：四兄弟对照

| 兄弟 | 拆了啥 | 病 |
|---|---|---|
| Standard | 全拆 | 裸考瞎猜 |
| CoT | 只留思考 | **闭卷推理，28% 失败是纯幻觉**——说得流畅但你没法分辨真假 |
| Act | 只留动作 | **没有工作记忆**：洗刀案——隔空洗刀、拿不存在的刀、原地打转 |
| ReAct | 不拆 | 幻觉 0%，但**推理错误 47%**（重复同一组动作出不了循环） |

- CoT 的知识来自模型记忆（可能是幻觉）；ReAct 的事实来自观察（有出处）
- ReAct 不封神：死循环是它的经典病 → "怎么防 Agent 死循环"是工程大专题

### 1.3 思考的本质 = 用文字当状态机

洗刀案的思考："现在我拿起了刀(1)。接下来，我需要去 sinkbasin 清洗它。"
——已完成记账 + 下一步宣告。跟 FoodRAG 槽位补全的 `answers` 字典同一件事，
只是状态记在上下文里给 LLM 自己看。

反面教材 ReAct-IM：只会复读"我需要找一把干净的刀"，**有思考≠会思考**，
思考必须对现状记账，不能是愿望复读机。

### 1.4 现代演化：文字协议退役，骨架没变

- 论文（2022）：模型不会调工具，用提示词**骗**它输出 `思考1:...动作1:Search[xxx]` 文字格式，再用正则抠
- 现在：模型**原生 function calling**，直接输出结构化 tool_calls（工具名+参数 JSON）
- 循环没变：`create_agent(model, tools, system_prompt)` 一行就是论文那个大循环

## 2. 实验记录（我自己跑出来的结论）

### 2.1 走法实验：轮数由什么决定

| 实验 | 输入 | 结果 |
|---|---|---|
| 并行 | 查上海+北京天气+算2*3（三件独立事） | **2 轮**：第1轮并行3个tool_calls → 第2轮收工 |
| 串行 | 先算2*3，再把结果乘以4（依赖） | **3 轮**：calculate("2*3") → calculate("6*4") → 收工 |

**沉淀三条：**

1. **依赖卡的是参数，不是任务**——第二算的参数"6"要从第一算的观察里拿，
   所以第1轮物理上只能发一个 tool_call
2. **工具签名表达力决定策略空间**：`calculate(expression)` 收任意表达式 → 有折叠成
   "2*3*4" 一步到位的空间；`multiply(a, b)` 固定参数 → 物理没法折叠。
   **宽合同灵活但 LLM 可能乱填；窄合同稳但轮数多、反问多**（槽位补全就是窄合同的代价）
3. **用户措辞是隐形指挥棒**："**先**…**再**…"就在指挥模型按步走（所以走了3轮教科书版）；
   想让模型一步到位，问题别写成流水账

### 2.2 模型性格对照（qwen vs DeepSeek 同题）

| | qwen3.7-flash | deepseek-flash |
|---|---|---|
| 台面思考 | 沉默干活（content=''） | "我来同时查询这三项信息。" |
| 台下思考 | reasoning_tokens 1349 | 33 |
| 收工话风 | 干巴巴 | 排版精美+追问 |

- **走法一致（循环结构决定），血肉是性格（模型决定）**
- DeepSeek 收工轮嘴痒：提议"北京未来几天的天气"——**工具库里没有这道菜**！
  → system_prompt 要写行为合同管住嘴
- **prompt cache 省账机关**：Agent 每轮全量重喂历史 → 第2轮 prompt 与第1轮前缀重叠
  → 命中提示词缓存打折（实测第2轮 600 token 里 384 命中）。多轮循环账单没想象中爆炸

### 2.3 收工判据（Finish 的现代版）

```python
if message.tool_calls:  # 还在点菜
else: final_answer = thought  # 不再点菜 = 收工，content 就是最终答案
```

- 论文里 Finish 是显式工具；现代 API 里"**不点菜本身就是收工信号**"
- `finish_reason`: `'tool_calls'`（点菜）/ `'stop'`（收工）——机器可读版
- ReAct 的收工可能"不来"（死循环）→ 要设最大轮数兜底

## 3. Plan-and-Execute：先画图，代码闭眼跑

### 3.1 LLM 只被叫醒两次

```
Plan（LLM①把需求翻译成JSON步骤数组）→ Execute（纯代码执行，零LLM）→ Summarize（LLM②翻译日志为人话）
```

- 贷款审批 3 步：ReAct 烧 4 次（3行动+1收工），P&E 固定 **2 次**
- **短路省钱**：validate 失败 return 写在循环**里面** → Summarize 不跑 →
  17 岁失败单只烧 **1 次**。风控场景被拒的多 → 短路省的是大头。
  （失败路径也要算成本，而且常常是主要成本——同 FoodRAG"缺药直接拒答不检索"）

### 3.2 依赖的两种解法（同一个问题的两副面孔）

| | ReAct | P&E |
|---|---|---|
| 解法 | **轮次**：等观察回来填参数 | **占位符**：`{step_2_result}` 预连线，规划时画好数据流 |

`fill()` 的 `fullmatch`：整段是占位符才替换——**认组合不认单蹦**
（同"周六的六不是6个人"：防误伤要靠组合拳）

### 3.3 分水岭：if 住在哪

> 新规矩"额度<申请就不许提交"——JSON 计划（数组）**天生没有 if**，表达不了。

| 出路 | 做法 | 代价 |
|---|---|---|
| if 住代码（P&E） | 像 validate 短路那样硬编码 | 每加一条规矩改一次代码 |
| if 住 LLM（ReAct） | 每轮看观察临场决定点不点菜 | 每步烧 LLM，判断不保证100%稳 |

**FoodRAG 判单树 = 纯 P&E；drug_rag 的 intent_classifier 开关 = 往 ReAct 挪半步。**

### 3.4 三模式总对照（毕业证）

| | ReAct | P&E | Self-Reflection |
|---|---|---|---|
| 对谁动手 | 环境（调工具） | 流程（画计划） | 自己（批改自己） |
| LLM 次数 | 轮数×1，越走越贵 | 固定 2 次（失败 1 次） | 固定 4 次 |
| 临场应变 | **有** | 无（计划锁死） | 无关（无工具） |
| 天生软肋 | 死循环 | 计划赶不上变化 | 改不了知识性错误 |
| 适合 | 探索型（多跳问答） | 流水线（步骤固定） | 高价值生成（长文/代码） |

## 4. Self-Reflection：自己改自己的卷子

### 4.1 四步流水线（零工具，纯 LCEL 管道）

```
思考（目标/步骤/风险）→ 初答 → 反思（正确?遗漏?错误?怎么修?）→ 修正
```

账本：多烧 3 次 LLM 换质量。**简单闲聊无需开启；高准确率需求开 1-3 轮**。

### 4.2 毕业证：反思的盲区

> 反思管**看得见的错**（超字数、漏要点、逻辑打架、格式违约）——自己能对账的；
> 救不了**知识性错误**——初答把 Python 诞辰写 1990，反思时它检查"答案符不符任务"，
> 不检查"1990 对不对"。**它要知道是1991，初答就不会错了。自己不知道自己错，就改不了。**

→ 外部裁判（ragas / eval / ground truth）**不可替代**：反思管质量，裁判管真实，别互相替代。

### 4.3 实测记录（lc_self_reflection.py）

- 简单任务现场：思考轮把活全干完，后面三轮传话筒——**仪式感烧 token**
- 但反思轮挑表述刺有点货："AI是…技术"略窄（也指学科）→ 修正版"**让机器**模拟"更准
- **LLM 数字数 = 拿不稳的工具干稳活**：`len()` 一行搞定的事别拜托 LLM。
  确定性信息不进 LLM，**确定性检查也别拜托 LLM**（同来源根治的哲学）

### 4.4 f-string 死模板坑（第三次见面）

```python
PromptTemplate.from_template(f"根据思考结果{think_result}，完成任务：{task}")
```

f-string 在造模板**之前**就把变量填了 → 模板没空可填 → `input_variables=[]`（实测铁证）。
**f-string 和 PromptTemplate 是两个填空引擎，别让 f-string 把模板的空提前填了。**
（第1次：ragas_demo 拼接坑；第2次：P&E 的 `{{}}` 转义当工具使；第3次：反面教材）

## 5. 工具设计三原则（给 Agent 发工具 = 给新员工发工牌）

1. **docstring 是菜单**：LLM 选工具的唯一依据。菜名对介绍歪 = 点错菜（同意图词表写歪方向）
2. **签名是合同**：参数收宽（表达式/问题）还是收窄（定死字段）——宽了灵活乱填，窄了稳但轮数多
3. **返回要诚实**：查不到就返回"未找到"，别编（同"宁可没有不推错的"）
