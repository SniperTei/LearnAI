# 采纳率、留存与业务指标

> 用户嘴上说好不好不重要，**用不用**最重要。
> 这才是 FDE 给客户讲的"真指标"。

---

## 业务指标的三层

```
体验层    👍率、满意度     →   "用户喜不喜欢"
使用层    采纳率、留存     →   "用户用不用"
业务层    ROI、效率提升    →   "客户赚没赚到/省没省到"
```

**FDE 越往后越值钱**——客户为业务结果付钱，不为满意度付钱。

---

## 体验层指标

| 指标 | 怎么算 | 何时用 |
|------|--------|--------|
| 👍 率 | 👍 / 总反馈 | 日常监控 |
| CSAT | 满意度问卷（1–5 星） | 定期 |
| NPS | "推荐给他人的概率 0–10" | 季度 |

**局限**：用户嘴上说的 ≠ 实际做的。
"A 我很喜欢！" → 然后再也没用过。

## 使用层指标（核心）

### 1. 采纳率（Adoption Rate）
```
采纳率 = 实际使用 AI 功能的用户数 / 目标用户数
```

例子：
- 公司 1000 人，AI 助手有权限
- 上周活跃用户 200 人
- **采纳率 = 20%**

**FDE 必报指标**。客户最关心"到底有多少人用起来了"。

#### 采纳率的细分
- **广度**：多少人用过（覆盖率）
- **深度**：每人用多少次（粘性）
- **频次**：每周用几次

```
覆盖率 = 用过的用户 / 总用户
粘性 = 周使用次数 / 周活跃用户
```

### 2. 留存率（Retention）
```
W1 留存 = 注册第 1 周的用户，在第 2 周仍然活跃的比例
W4 留存 = 第 4 周仍然活跃的比例
```

**留存比拉新更重要**。
- 采纳率 50% 但留存 10%：用户试一下就走，**产品有问题**
- 采纳率 20% 但留存 80%：种子用户喜欢，**有未来**

### 3. 接管率（Takeover Rate / Override Rate）
```
接管率 = 用户修改 AI 答案后使用的次数 / AI 给出答案的总次数
```

**最强负信号**：用户嫌错到自己改。

细分：
- 小改（typo、措辞）→ 可接受
- 大改（事实、结论）→ AI 质量问题
- 完全重写 → AI 完全失败

### 4. 任务成功率（Task Completion Rate）
```
任务成功率 = 用户达成目标的会话数 / 总会话数
```

例：用户问"怎么报销"，AI 真的帮 ta 完成报销 → 1；用户最后放弃 → 0。

**难点**：怎么定义"成功"？
- 显式：用户最后说"谢谢 / 搞定了"
- 隐式：用户后续行为（如点击了"已解决"按钮）
- 业务：实际完成了对应业务动作（如真提交了报销单）

### 5. 替代率（Displacement Rate）
```
替代率 = AI 处理的任务数 / (AI + 人工) 处理的任务数
```

例：
- 客服工单总共 1000/月
- AI 自动处理了 300 个
- 人工处理了 700 个
- **替代率 30%**

这是给 CFO 看的指标——直接对应省钱。

## 业务层指标（客户最爱听）

### 1. 节省时间
```
单次任务平均节省时间 × 任务数 = 总节省时间
```

例子：
- 律师查条款，原本 20 分钟，AI 辅助 5 分钟
- 每月 500 次查询
- **节省时间 = (20 - 5) × 500 = 7500 分钟 = 125 小时**

按律师时薪 ¥2000 → **每月省 ¥25 万**。

### 2. 节省成本
```
替代人工的成本 - AI 成本 = 净节省
```

### 3. 收入提升
更难算，但杀伤力最强。
- AI 推荐提升转化率 5% → 直接对应 GMV
- AI 客服减少流失 → 对应 LTV

### 4. 错误率降低
- AI 自动检查减少人为错误
- 在合规、风控、医疗场景尤其值钱

### 5. 响应速度
- 客服从平均 4 小时响应 → 30 秒响应
- NPS 提升 / 客户流失率下降

## 怎么"算"业务 ROI（FDE 必备技能）

### ROI 模板

```
【成本侧】
- 开发成本：FDE 工时 × 月数（一次性）
- 运营成本：模型 API + 基础设施（每月）
- 维护成本：1 个工程师部分时间（每月）

【收益侧】
- 节省时间 × 单位时间价值
- 替代人工的工资
- 错误减少避免的损失
- 收入提升（如可量化）

【ROI 计算】
ROI = (累计收益 - 累计成本) / 累计成本
回本周期 = 开发成本 / 月度净收益
```

### 一个真实例子（律所 RAG）

```
成本：
- 开发：2 FDE × 3 月 + 1 月部署 = ¥40 万
- 运营：API + 服务器 = ¥8000/月
- 维护：0.2 工程师 = ¥6000/月
- 总月运营：¥1.4 万

收益：
- 50 律师 × 节省 5 小时/周 × ¥1500/小时 × 4 周 = ¥150 万/月

回本周期：¥40 万 / (¥150 万 - ¥1.4 万) ≈ 0.27 月 ≈ 8 天

年 ROI: (1800 - 40 - 17) / 57 ≈ 30 倍
```

**这就是 FDE 卖方案的语言**。
技术指标（faithfulness 0.9）客户无感，"8 天回本"客户立刻签合同。

## 指标陷阱

### 陷阱 1：虚荣指标
- 注册用户数：用户注册了不代表用
- 总请求量：用户无聊问 AI 也算
- 准确率：在没有业务对齐时没意义

**对策**：每个指标问"这能转化为业务价值吗？"

### 陷阱 2：选择性汇报
- "AI 准确率 95%！"——但只测了简单 case
- "用户满意度 4.8！"——但只有 5 个反馈

**对策**：所有指标配**样本量**和**置信度**。

### 陷阱 3：因果 ≠ 相关
- 上线 AI 后，NPS 提升 5 分
- 不一定是 AI 的功劳——可能竞对出事了

**对策**：A/B 测试 + 排除外部因素

### 陷阱 4：短期数据误导
- 上线第一周采纳率 80%——新鲜感
- 三周后 → 20%

**对策**：看长期趋势，不看首周数据

## Dashboard 设计

### 给工程团队看的
- 延迟 P50/P95/P99
- 错误率
- 成本 / 1k 请求
- Faithfulness 趋势

### 给业务方看的
- 采纳率
- 节省时间（累计）
- 替代率
- ROI

### 给客户高管看的
- 1 张图：业务价值 vs 成本
- 3 个数字：节省时间 / 节省成本 / 错误降低
- 1 个故事：最有代表性的 case

**不同受众，不同指标**。FDE 的沟通能力之一。

## 实战：my_com_rag 的指标体系

### 离线（每周跑）
- Faithfulness / Answer Relevancy
- Context Precision / Recall
- golden set 准确率

### 在线（实时）
- 日活 / 周活
- 每用户日均使用次数
- 👍率 / 接管率
- 任务完成率（按场景分桶）
- P95 延迟 / 错误率

### 业务（每月）
- 假设场景：节省时间 / 节省成本
- 实际 ROI（如果能跟踪）

### 客户报告（每季度）
- 一页纸：本月本系统为业务创造了 X 价值
