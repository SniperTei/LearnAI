# 评估分类框架（Eval Taxonomy）

> 一张地图，让你看清楚"我现在在评什么、还缺什么"。

---

## 按维度一：评估对象（评什么）

| 对象 | 评什么 | 典型指标 |
|------|--------|----------|
| **检索（Retrieval）** | 召回的文档对不对 | Context Precision / Recall / MRR / NDCG |
| **生成（Generation）** | 答案好不好 | Faithfulness / Answer Relevancy |
| **任务（Task）** | 端到端完成度 | 任务成功率 / 工具调用正确率 |
| **体验（UX）** | 用户感受 | 满意度 / NPS / 留存 |
| **成本（Cost）** | 性价比 | 每次调用成本 / token 效率 |
| **安全（Safety）** | 不出事 | 拒答率 / 越狱成功率 / 偏见 |

**一个常见错误**：只评"生成"——其实检索挂了一样全盘皆输。

---

## 按维度二：评估时机（什么时候评）

```
开发阶段     离线评估    每次改 prompt / 模型 / 数据 → 跑 golden set
预发布      回归测试    上线前对比上一版本，确认不退步
灰度阶段    影子评估    线上流量复制 → 离线评估，不影响用户
上线后      在线评估    真实反馈、A/B、行为指标
```

---

## 按维度三：评估方法（怎么评）

| 方法 | 成本 | 速度 | 可信度 | 何时用 |
|------|------|------|--------|--------|
| **规则匹配** | 极低 | 极快 | 低 | 简单 factoid、关键字匹配 |
| **Embedding 相似度** | 低 | 快 | 中 | 开放生成、语义近似 |
| **LLM-as-Judge** | 中 | 中 | 中-高 | 主观质量、维度评估 |
| **Pairwise 对比** | 中 | 中 | 高 | A vs B 谁更好 |
| **专家人工标注** | 极高 | 慢 | 极高 | 校准其他方法、关键场景 |

**最佳实践**：金字塔——大量规则/embedding 当底，LLM-as-Judge 中间，少量人工校准塔尖。

## 按维度四：评估粒度（评多细）

### Sample 级（单条）
对一条 query-response 打分。
```
Q: "公司年假多少天"
A: "入职即享 15 天"
Score: 1.0（正确）
```
**用例**：golden set、CI 测试。

### 会话级（多轮）
对整个对话流程打分。
```
User: 我要请假
AI: 请问几天？
User: 3 天
AI: 已提交，单号 X123
Score: 任务成功 = 1
```
**用例**：Agent / 多轮客服。

### 系统级（聚合）
对整个系统的整体质量打分。
```
本月平均 faithfulness: 0.87
平均延迟: 1.8s
用户 👎 率: 8%
```
**用例**：上线决策、版本对比、SLA。

## 完整评估矩阵

把上面 4 个维度组合，FDE 上线一个项目通常需要：

```
                      检索   生成   任务   体验   成本   安全
─────────────────────────────────────────────────────────────
规则/embedding        ✅     ✅    —     —     —     ✅
LLM-as-Judge          ✅     ✅    ✅    ✅     —     ✅
专家人工              ⭐     ⭐    ⭐    ⭐     —     ⭐
A/B 测试              —      —     —     ✅     —     —
行为指标              —      —     ✅    ✅     ✅     —
```
（⭐ = 用于校准，量少但精）

**没有任何一行能覆盖所有列**——这就是为什么评估是体系，不是工具。

## 评估目标决定方法选择

### 场景 A：我要决定 v2 是否上线
- 方法：Golden set + LLM-as-Judge + 与 v1 pairwise 对比
- 决策：v2 在主要指标上 ≥ v1，且关键 case 不退步 → 上线

### 场景 B：我要知道系统在真实用户上表现
- 方法：在线反馈采集 + 采纳率/接管率 + A/B 测试
- 决策：综合 1–2 周数据，看是否扩大流量

### 场景 C：客户问"你们质量怎么样"
- 方法：选 5 个 KPI（faithfulness / 准确率 / 延迟 / 拒答率 / 满意度），给数字 + 同比
- 关键：**讲故事**——指标 + 改进轨迹 + 下一步计划

### 场景 D：我改了 prompt，要快速验证
- 方法：跑 20 条核心 case，看 faithfulness 不掉
- 工具：CI 接入 golden set

## FDE 评估能力阶梯

```
Level 0  没评估（凭感觉）
─────────────────────────
Level 1  有 golden set，但没指标（人工看）
─────────────────────────
Level 2  有 LLM-as-Judge，跑量化分数
─────────────────────────
Level 3  有离线 + 在线 + 人在环，闭环迭代
─────────────────────────
Level 4  评估自动化、CI 化，回归测试守护每次发布
─────────────────────────
Level 5  评估反哺业务（发现了客户自己都没察觉的问题）
```

**目标**：6 个月做到 Level 3，1 年冲 Level 4。

---

## 你需要建的最小评估工具箱

按投入产出排序：

1. **Golden Set**（50–100 条）—— 一切评估的地基
2. **LLM-as-Judge**（一个统一打分 prompt）—— 量化主力
3. **RAGAS / 类似框架**—— RAG 场景必装
4. **在线反馈采集**（前端 👍👎）—— 在线评估入口
5. **评估 dashboard**（哪怕 Notion 表格）—— 让指标可见

**不追求完美，追求闭环**：先有，再优化。
