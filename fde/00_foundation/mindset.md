# FDE 的思维方式（Mindset）

技术可以现学，**思维方式是 FDE 真正的护城河**。
一个工程师转 FDE 最难的不是学新技术，而是**换操作系统**。

---

## 五个核心思维

### 1. 假设驱动（Hypothesis-Driven）

**普通工程师思维**：客户说要 X，我就做 X。
**FDE 思维**：客户说要 X，**他真正想解决的问题是什么？X 是最优解吗？**

#### 实践模板
```
观察：客户说"我要个 AI 客服"
假设：客户的真实痛点是工单响应慢，影响 NPS
验证方法：
  - 看现在的工单数据：平均响应时间？
  - 简单 FAQ 是否占大头？
  - 人工成本多少？
最小验证实验：
  - 用 50 条历史 FAQ 搭个 RAG
  - 给 1 个客服试用 1 周
  - 看响应时间是否下降
```

**为什么重要**：客户经常描述"他们以为的解决方案"，不是问题本身。
FDE 的价值之一是**帮客户重新定义问题**。

---

### 2. 客户成功优先（Customer Success First）

**代码是手段，客户成功是目的。**

#### 决策框架
当面临技术选择时，按这个顺序问：

```
1. 客户会因为这个选择而更成功吗？
2. 客户能感知到这个选择吗？
3. 这个选择是否影响交付时间？
4. 这个选择的工程美感 / 技术先进性？
```

**4 永远是最后一位**。

举例：
- 客户提了个紧急需求 → 用 OpenAI API + Streamlit 一天搞出来 vs 自己训模型一个月 → **选前者**
- 内部 demo vs 给客户用的生产环境 → 后者**必须**加评估和监控
- LangChain vs 自己写 → 客户环境能不能装？谁好维护？**不是**哪个更新更酷

---

### 3. 模糊性容忍（Ambiguity Tolerance）

**FDE 永远在信息不全的情况下做决策。**

#### 4 个常见模糊场景

| 场景 | 普通 SDE 反应 | FDE 反应 |
|------|---------------|----------|
| 需求不清 | "把 PRD 给我" | "我先做个最简单版本，看客户反应" |
| 数据脏 | "先清洗完再说" | "用脏数据先跑，看错误模式再清洗" |
| 评估指标缺失 | "等业务定义 KPI" | "先自己定个代理指标，跑起来再校准" |
| 模型效果不确定 | "再调几版 prompt" | "上线，看真实用户反馈" |

**核心**：先有一个能验证的东西，**优于**一个完美的计划。

---

### 4. 反馈闭环（Feedback Loop）

FDE 的工作价值 = 反馈循环的速度 × 循环次数。

#### 快速循环模板
```
Day 1   需求假设
Day 2   最小原型（ ugly but works ）
Day 3   1–2 个用户试用
Day 4   收集反馈 → 改方案
Day 5   再次试用 + 决策：放大 or 关停 or 转向
```

**一周一个循环**是 FDE 的健康节奏。
如果一个项目两个月没让真实用户用过——基本是死的。

---

### 5. 业务语言（Speak the Business）

**用客户的语言沟通，不要用技术术语。**

| ❌ 不要说 | ✅ 要说 |
|----------|---------|
| "我用了 RAG + gpt-4" | "系统会自动查你们的内部文档，回答准确率我们从 60% 提到了 85%" |
| "这个用 cosine similarity" | "系统会按相关度排序，把最相关的条款排在最前面" |
| "Agent 偶尔会 hallucinate" | "AI 会有 5% 的概率说错，所以关键决策我们加了人工复核" |
| "Latency 降低了 200ms" | "响应速度从 2 秒变到 1.8 秒，用户感知更顺滑" |

**练习**：每次写完技术方案，强迫自己用 1 段话向不懂技术的人解释价值。

---

## 一个反直觉的认知：FDE 的"懒"

**优秀的 FDE 是"懒"的——能不写代码就不写。**

决策树：

```
这个问题真的需要 AI 吗？
├── 不需要 → 用规则 / 数据库查询 / Excel 宏
├── 需要一点点 → Prompt + 简单流程
├── 需要中等 → RAG / Function Calling
└── 真的需要复杂 → Agent / Fine-tune
```

**永远从最简单的方案开始**。简单方案能解决 80% 的问题，没必要上复杂架构。

---

## FDE 的反模式（Anti-patterns）

❌ **过度工程化**：客户要个 FAQ 机器人，你搭了 5 个 Agent 协作
❌ **追新技术**：客户用得好好的 GPT-4，你非要换 Claude（除非有明确收益）
❌ **忽视评估**：上线后不知道好不好用，只能凭"我感觉"
❌ **不沟通只干活**：做了 2 周发现客户要的是另一个东西
❌ **代码先于问题**：先选了 LangGraph，再想这事儿用不用得上 Agent
❌ **不敢说不**：客户提的所有需求都接，最后项目失控

## 思维方式自测题

回答这些问题，看自己现在的思维更像 SDE 还是 FDE：

1. 上次你写的技术方案，第一段写的是技术选型还是业务价值？
2. 你能不查文档，用 3 句话向家人解释 RAG 吗？
3. 你做过"先用最丑的方式验证假设"的决策吗？
4. 你上一个项目的成功指标，是技术指标还是业务指标？
5. 客户/用户给过你**意外**的反馈吗？你怎么处理的？

> 答案没有标准。但**诚实回答**这件事本身，就是 FDE 的训练。

## 思维习惯清单（每天练）

- [ ] 看到任何 AI 产品，问："它用了什么数据？怎么评估？谁付钱？"
- [ ] 读到任何技术文章，问："这个技术在什么场景下**不**该用？"
- [ ] 写代码前，问："这事儿一定要写代码吗？"
- [ ] 推介方案前，问："客户听完会愿意付钱吗？多少钱？"
- [ ] 每天用 1 分钟向自己解释："我今天解决的问题，业务价值是什么？"
