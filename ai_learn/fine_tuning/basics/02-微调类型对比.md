# Fine-tuning 类型全解析

## 按参数更新方式分类

### 1. Full Fine-tuning (全量微调)
更新模型的所有参数。

```
预训练参数: 7B (如 LLaMA-7B)
微调更新: 7B
参数量: 7B
```

**特点**:
- ✅ 效果最好
- ❌ 需要大量显存 (7B模型需要 ~140GB)
- ❌ 训练慢
- ❌ 每个任务需要独立模型

**适用场景**:
- 资源充足
- 追求最佳效果
- 长期使用的核心模型

---

### 2. Parameter-Efficient Fine-Tuning (PEFT)

只更新少量参数，冻结大部分参数。

#### 2.1 LoRA (Low-Rank Adaptation)

**核心思想**: 在权重矩阵旁边添加低秩矩阵

```
原始权重: W (d × d)
LoRA添加: A (d × r) 和 B (r × d)，其中 r << d
前向传播: h = Wx + BAx
微调参数: 仅更新 A 和 B
参数量: 2 × d × r (r 通常取 8-64)
```

**示例**:
- LLaMA-7B: r=16 时，只更新 ~40M 参数 (< 1%)
- 显存需求: ~16GB (vs 全量的 ~140GB)
- 效果: 接近全量微调

**LoRA 优势**:
- 🚀 显存占用极低
- 💾 可以共享基础模型，只存储轻量级 adapter
- 🔄 切换任务只需加载不同 adapter
- 📈 性能接近全量微调

#### 2.2 QLoRA (Quantized LoRA)

**核心思想**: LoRA + 4位量化

```
基础模型: 4位量化 (NF4/FP4)
可训练部分: LoRA adapter
显存需求: 进一步降低 50%
```

**示例**:
- LLaMA-65B 可在单张 48GB 显存 GPU 上微调
- 性能几乎无损

#### 2.3 Prefix Tuning

**核心思想**: 在每层添加可训练的 prefix tokens

```
输入: [PREFIX][x1][x2]...[xn]
PREFIX: 可训练的连续向量
```

#### 2.4 Prompt Tuning

**核心思想**: 只在输入层添加可训练的 prompt

```
输入: [PROMPT][实际输入]
PROMPT: 可训练的软提示
```

**特点**:
- 参数量最少 (每任务只需几万个参数)
- 大模型上效果好（> 10B 参数）

## 按任务类型分类

### 1. 指令微调 (Instruction Tuning)

**目标**: 让模型更好地理解 and 执行指令

**数据格式**:
```json
{
  "instruction": "解释什么是量子计算",
  "input": "",
  "output": "量子计算是一种利用量子力学原理..."
}
```

**示例**:
- Alpaca (Stanford): 52K 指令数据
- FLAN (Google): 多任务指令混合

**效果**:
- 提升指令跟随能力
- 改善多任务表现
- 增强零样本学习能力

---

### 2. 对话微调 (Chat Fine-tuning)

**目标**: 让模型进行多轮对话

**数据格式**:
```json
{
  "conversations": [
    {"from": "human", "value": "你好"},
    {"from": "assistant", "value": "你好！有什么可以帮你的？"},
    {"from": "human", "value": "介绍一下你自己"},
    {"from": "assistant", "value": "我是AI助手..."}
  ]
}
```

**示例**:
- ChatGPT (OpenAI)
- LLaMA-2-Chat
- ChatGLM

**关键点**:
- 多轮对话上下文理解
- 自然流畅的回复
- 避免重复和无关回答

---

### 3. 领域微调 (Domain Adaptation)

**目标**: 适配特定领域的语言和知识

**示例**:
- BioMedLM: 生物医学领域
- LawGPT: 法律领域
- FinGPT: 金融领域

**数据**:
- 领域内文本继续预训练
- 领域特定的问答对

---

### 4. 奖励模型微调 (Reward Modeling)

**目标**: 学习人类偏好

**数据格式**:
```json
{
  "prompt": "写一首关于春天的诗",
  "chosen": "春风拂面柳丝长...",
  "rejected": "春天是温暖的季节..."
}
```

**用途**:
- RLHF (Reinforcement Learning from Human Feedback)
- DPO (Direct Preference Optimization)

---

## 如何选择微调方法？

### 决策树

```
开始
  ↓
显存 >= 80GB?
  ├─ 是 → Full Fine-tuning
  └─ 否 ↓
      模型 > 30B?
      ├─ 是 → QLoRA
      └─ 否 ↓
          追求最佳效果?
          ├─ 是 → LoRA
          └─ 否 → Prompt Tuning / Adapter
```

### 推荐配置

| 场景 | 模型大小 | GPU | 推荐方法 |
|------|---------|-----|---------|
| 个人学习 | 7B | 16GB | QLoRA |
| 小团队 | 13B | 24GB | LoRA |
| 企业生产 | 70B | 4×A100 | Full / QLoRA |
| 多任务切换 | 7B | 16GB | LoRA + 多adapter |

---

## 实际案例对比

### 案例分析：LLaMA-7B 不同微调方法

| 方法 | 参数量 | 显存 | 训练速度 | MMLU得分 |
|------|-------|------|---------|---------|
| Base | 0 | 14GB | - | 35.1 |
| Full | 7B | 140GB | 1× | 45.2 |
| LoRA r=8 | 40M | 16GB | 1.2× | 44.8 |
| QLoRA r=16 | 80M | 12GB | 0.9× | 44.5 |

**结论**: QLoRA 性价比最高

---

## 小测验

**问题**: 你有一个 A100 (40GB) GPU，想微调 LLaMA-33B 模型用于医疗问答，应该选择什么方法？

**答案**: QLoRA
- LLaMA-33B 全量微调需要 > 200GB 显存
- LoRA 仍需要 ~80GB (16位)
- QLoRA 只需要 ~35GB (4位基础模型 + LoRA)
